# 🚀 My First CI/CD Pipeline

**Автор:** Абрамов Даниил Сергеевич

Первый учебный проект с использованием **GitHub Actions**.

Цель проекта — настроить простой CI workflow, который автоматически запускается при каждом `push` в репозиторий и выполняет тестовую команду в среде GitHub Actions.

---

## 🎯 Цель проекта

В рамках проекта необходимо было:

- создать отдельный GitHub-репозиторий
- настроить структуру GitHub Actions
- создать первый workflow
- настроить автоматический запуск при каждом push
- выполнить команду внутри CI
- проверить успешное выполнение workflow во вкладке Actions

---

    my-first-cicd/

    └── .github/
        └── workflows/

GitHub автоматически определяет workflow-файлы, расположенные в каталоге:

---

## ⚙️ Workflow

Основной workflow находится в файле:

    .github/workflows/hello.yml

Содержимое:

    name: Мой первый workflow

    on: [push]

    jobs:
      build:
        runs-on: ubuntu-latest

        steps:
          - uses: actions/checkout@v4

          - name: Запустить команду
            run: echo "Привет, мир! Я только что запустил CI!"

## 🔄 Как работает Pipeline

После каждого push в репозиторий автоматически запускается workflow.

Процесс выполнения выглядит так:

    Git Push
       │
       ▼
    GitHub Repository
       │
       ▼
    GitHub Actions
       │
       ▼
    Ubuntu Runner
       │
       ▼
    Checkout Repository
       │
       ▼
    Execute Command
       │
       ▼
    Workflow Success ✅

---

## 🧩 Этапы выполнения

### 1. Trigger

Workflow запускается автоматически при событии:

    push

То есть при каждом новом push в репозиторий.

---

### 2. Runner

Для выполнения используется виртуальная машина:

    ubuntu-latest

GitHub самостоятельно создаёт временное окружение для выполнения job.

---

### 3. Checkout

На первом шаге используется:

    actions/checkout@v4

Этот action загружает содержимое текущего репозитория внутрь GitHub Runner.

---

### 4. Выполнение команды

Следующий шаг выполняет обычную shell-команду:

    echo "Привет, мир! Я только что запустил CI!"

В логах GitHub Actions отображается результат её выполнения.

---

## ✅ Результат

После отправки изменений в ветку main workflow запускается автоматически.

При успешном выполнении GitHub показывает зелёную галочку.

Это означает, что:

- workflow-файл прочитан корректно
- GitHub Actions запустил Runner
- репозиторий успешно загружен
- команда была выполнена без ошибок
- CI pipeline завершился успешно

---

## 🖥️ Проверка в GitHub

Проверить выполнение workflow можно:

1. открыть репозиторий на GitHub
2. перейти во вкладку **Actions**
3. выбрать **Мой первый workflow**
4. открыть job `build`
5. проверить выполнение всех шагов

Успешный запуск отображается зелёной галочкой.

## 📌 Что такое CI

**CI — Continuous Integration** — практика непрерывной интеграции изменений в проект.

Основная идея заключается в том, что после каждого изменения система автоматически выполняет заданные проверки.

В реальных проектах CI может выполнять:

- запуск тестов
- проверку качества кода
- сборку приложения
- линтинг
- проверку зависимостей
- создание Docker-образов
- публикацию артефактов

В данном проекте используется самый простой пример — выполнение одной команды.
